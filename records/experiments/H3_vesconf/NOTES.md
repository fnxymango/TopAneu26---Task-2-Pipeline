# H3 — 곁가지 신뢰도(vesconf) 피처 (준비 완료 · H2 판정 후 실행)

## 무엇을 바꾸나 — 피처 블록 하나 추가

`c5_location_v2.py` 의 `TOPANEU_VESCONF` 환경변수만 켠다. 다른 건 전부 기준팔과 동일하다.

| 모드 | 하는 일 | 차원 |
|---|---|---|
| `off` | 기존 (기준팔) | 112 |
| `block` | conf 36차원을 뒤에 붙인다 — RF 가 쓸지 말지 스스로 정한다 | 148 |
| `gate` | 거리/중첩 피처에 conf 를 곱한다 — 허깨비 신호를 직접 누른다 | 112 |

`conf[c] = clip(최대연결성분_복셀[c] / 학습292중앙값[c], 0, 2)`.
진짜 혈관은 굵고 이어진 관이고 허깨비는 작고 끊긴 조각이라는 전제.
기준 중앙값을 **학습 케이스에서만** 잡으므로 val/test 누수가 없다.
표: `code/sblee/nnunet/analysis/vesconf_{train,val,test}.json` (2026-08-25 · `p_vesconf.py` 생성).

## 왜 — 관찰 근거와 그 한계

`bpfalse.py` 로 검출된 107병변을 조사했다 (제출본 구성 `b1on_pf`, 5시드).

| 구분 | 병변 | 분류 정답률 |
|---|---|---|
| 전체 | 107 | 69.0% |
| 가장 가까운 분기점이 **거짓**(GT 에 대응 노드 없음) | 17 | 54.1% |
| 〃 진짜 | 90 | 71.8% |
| 병변 5mm 안에 **가짜 곁가지**(예측만 있고 GT 엔 없음) | 15 | 54.7% |
| 〃 없음 | 92 | 71.3% |
| ICA 중 가짜 곁가지 있음 | 7 | 48.6% |
| ICA 중 없음 | 35 | 67.4% |

가짜 곁가지 내역 **L-Pcom 7 · L-AChA 5 · R-AChA 4 · R-Pcom 3 · R-OA 1** — ICA 사이펀 분절
경계를 정의하는 바로 그 분지들이다. `p_vesconf.py`(2026-08-25)의 진단과 일치한다:
"예측 혈관에서 Pcom/AChA 가 GT 대비 1.31~1.46배 과대 등장한다 … 최다 오답이 전부 → Pcom-junction".

**한계 — 이 관찰만으로는 결론이 안 난다.**
- 표본이 작다 (n=7~11).
- 분기점 밀도와 교란된다 (밀도 vs 거짓 분기점 수 r=0.54). 밀도를 층으로 통제하면
  각 층의 '거짓' 표본이 n=5·3·9 로 쪼개져 판정 불가가 된다.
- 밀도 자체는 원인이 아니다 — **ACA 는 밀도 7.8 로 가장 빽빽한데 정답률 81% 로 가장 높다.**
  (MCA 2.9/81.5% · 후순환 5.9/47.8% · ICA 7.3/64.3% · ACA 7.8/81.0%)
- 후순환이 47.8% 로 가장 나쁜 이유는 밀도로도 가짜 곁가지로도 설명되지 않는다. 미해결.

그래서 관찰 표본(n=11)을 실험 표본(130병변 × 5시드)으로 대체한다.

## 판정규칙 (H3.sh 머리말에 고정)

각 모드에 대해 `{mode}_pf − {기준}_pf` 가 신 eval 6지표 중 ≥4 개선 ∧ 평균 ΔMCC ≥ 0 을
**test·val 둘 다** 만족하면 채택. 둘 다 통과하면 ΔMCC 가 큰 쪽. 시드 산포가 평균보다
크면 명시. 기전 확인(`h3_mech.py`)으로 **가짜 곁가지가 있던 15병변에서 실제로 올랐는지**를
따로 본다 — 전체가 올라도 거기서 안 오르면 다른 이유로 오른 것이다.

**검출력 한계 명시**: `chain_v3.sh`(2026-08-25)는 val 42 의 검출력이 없다고 판단해
주 관문을 292 OOF 로 옮겼었다. 그 검출 결과(`aneu_train_ooff`)를 2026-09-08 정리 때
삭제해 재현이 불가하다. 대체 관문이 없으므로 표준 두 집합 규칙을 쓰되, val 이
+0.018 수준의 진짜 효과도 t=2.3 밖에 못 내는 관문이라는 점을 결론에 적는다.

## 실행

```bash
# H2 에서 개정피처가 채택된 경우
bash H3.sh b1Non e11_feat_hyb_ov_NEW.json 2
# 미채택 → 제출본 그대로가 기준
bash H3.sh b1on  e11_feat_hyb_ov.json     2
```
기준팔은 H1/H2 산출물을 그대로 쓰고 재계산하지 않는다. 새로 도는 것은 vesconf 두 팔뿐이다.
0단계에서 vesconf 표 커버리지와 **vesconf 가 vespp 보다 나중에 생성됐는지**를 검사하고,
1단계 후 로그에 `[vesconf]` 가 찍혔는지 확인한다 — 조용히 off 로 돌면 기준팔과 같은 결과가 나와
"효과 없음"으로 오독된다.
