## 1. 지표 재확인 (evaluate.py 정독)
- 랭킹 점수 = `mean(P, R, MCC, Dice, VolSim, 1−HD95)`, **52로 나눔**(`evaluation_average`).
- `tp/fp/fn` 은 **클래스×케이스 0/1**, 케이스 합산 뒤 클래스별 지표 계산.
- `Dice/VolSim/HD95` 는 **복셀 단위**를 케이스 합산 후 `(TP+FN+FP)` 로 나눔.
- GT·예측 모두 없는 클래스는 Dice/VolSim/HD95 = 0 (TN 은 점수에 안 들어감).

## 22. 채택 ② — `TOPANEU_TOPK_FRAC` (2등 클래스 복셀 지분)

### 착안
게이트가 발동한 blob 에서 **2등 정답률이 1등 이상**이다:
```
split  발동  1등정답  2등정답  둘다틀림
train   40      6       8       26
test    13      3       4        6
val      5      2       2        1
```
TP 성립은 1복셀이면 되지만 Dice·VolSim 은 복셀 지분에 비례한다. 그런데 2등이 받던 건
중앙 blob 281복셀 중 **3복셀(1%)** 이었다. 둘 다 틀린 경우(26/40)는 어느 쪽도 Dice 를
못 받으므로 지분을 늘려도 손실이 없다. 그리고 `|P∩G|/|P| = 0.945` 라 blob 의 94.5% 가
GT 안이므로 쪼개도 양쪽 다 GT 와 겹친다.

### e2e 응답곡선 (기준선 d2007, CLF_SEED=3)
```
FRAC    test      val       train OOF 292
0.05   +0.0006   +0.0009   +0.0002
0.10   +0.0012   +0.0014
0.20   +0.0023   +0.0021   +0.0006
0.35   +0.0034   +0.0025   +0.0008     ← val 정점
0.50   +0.0042   +0.0025
0.65   +0.0047   +0.0017
0.80   +0.0049   +0.0002               ← test 포화 · val 붕괴
```
7개 지점 **전부 두 집합 양수**. val 이 뒤집힌 U 자를 그리고 test 가 포화하는 형태 —
잡음이면 나오지 않는 모양이고, 정점 위치도 위 적중 빈도(test 3:4, val 2:2)와 맞는다.

### 세 집합 모두에서 TP/FP/FN 완전 불변
```
test 52/50/33 · val 26/20/18 · train OOF 160/234/100  ← 지분과 무관하게 동일
PREC·RECA·MCC 소수점까지 불변, DICE·VOLSIM 만 상승
```
**P/R/MCC 가 정의상 불변이라 과적합할 자유도가 없다.**

### 시드 견고성 (짝지은 3시드)
```
test 시드0 +0.0028 · 시드1 +0.0040 · 시드3 +0.0042   평균 +0.0037 · 3/3
val  시드0 +0.0025 · 시드1 +0.0025 · 시드3 +0.0025   평균 +0.0025 · 3/3
```
짝지은 6개 비교 전부 양수. val 이 세 시드 모두 동일한 것은 게이트가 5개 blob 에만
발동하고 효과가 복셀 지분 계산이라 시드와 무관하기 때문 — 메커니즘상 그래야 맞다.

⚠ **기준선 자체가 시드마다 다르다**(test 0.2880 / 0.2974 / 0.3011). 시드 3 이 우연히
가장 좋은 기준선이다. 판정은 짝지은 Δ 라 영향 없지만, **Notion 표에 절대값을 올릴 때는
시드 선택을 다시 봐야 한다.**

### 시험할 필요 없이 닫은 조합
- **3등까지 지분** — 3등 정답이 train 3/40 · test 0/13 으로 1·2등보다 훨씬 드물다.
  자주 맞는 쪽에서 뺏어 드물게 맞는 쪽에 주는 셈.
- **슬라이버 배치(`TOPK_SHAPE`)** — `|P∩G|/|P| = 0.945` 라 어떻게 쪼개도 각 조각의
  94.5% 가 GT 안. Dice 기여가 배치가 아니라 복셀 수에만 비례한다.
- **게이트 없이 전체 blob 에 지분** — 무조건 2등 적중률 test 7.7% vs 1등 72.7%.

## 23. min_vox=20 — train OOF 292 3차 확인 (단가표의 예측력 검증)
```
train OOF 292    TP   FP   FN     6지표      Δ
min_vox  5      158  217  102    0.2297      —
min_vox 20      156  191  104    0.2378   +0.0080
```
train OOF 에서는 **무손실이 아니다** — TP 2개를 잃고 FP 26개를 없앤다(test·val 은 TP 불변).
단가표로 계산하면 `2×(−0.0110) + 26×(+0.0012) = +0.0092`, **실측 +0.0080**.
→ 단가표가 사후 설명이 아니라 **예측력이 있다**(게이트 실험 사전 예측에 이은 두 번째 검증).

## 24. 최종 구성 — 세 집합 전부 확인

```
min_vox 5→20     +0.0059  +0.0019     +0.0080
```

# 2부 — MCC 기준 재검토 + 과적합 검사 도입 (2026-09-02 오전 KST)

## 25. 지표 분모를 두 개로 병기한다
`evaluation_average` 는 **52로 나눈다**(리더보드 기준). c5 의 `adjusted_div_present` 는
그 split GT 보유 클래스만 평균한다(covered_gt, test 36 · val 33 · train 43).
**MCC 는 두 분모가 정확한 배수 관계다** — GT 없는 클래스의 MCC 가 정확히 0 이라
`MCCcg = MCC52 × 52/n_pres`. 6지표는 HD95 항 때문에 배수가 아니다.
```
현재 확정본(fr050 = min_vox20 + FRAC0.50)
  test  MCC 0.2884(div52) / 0.4166(cg) · 6지표 0.3053 / 0.3669
  val   MCC 0.3036 / 0.4784           · 6지표 0.3243 / 0.4201
```

## 26. MCC 는 마스크 모양에 구조적으로 눈이 멀었다
MCC 는 (케이스×클래스) 0/1 집합만 본다. 그래서 **복셀 재분배·정규화·크기조정은 ΔMCC = 0 이
보장된다.** 오늘 채택한 `min_vox 20`·`TOPK_FRAC`·적응형 리사이즈가 전부 여기 해당한다.
부트스트랩 1000회에서 `TOPK_FRAC` 의 ΔMCC 가 **전 재표본 정확히 0.0000** 으로 확인됐다.
→ MCC 를 올리려면 **예측되는 클래스 집합**을 바꿔야 한다. 다른 길이 없다.

## 27. 단가와 손익분기 (MCC 담당 · 공식 채점 재현 확인)
```
TP=0 클래스에 TP 하나 만들기   +0.0135 (한번도 예측 안 된 클래스면 +0.0192)
TP>0 클래스의 FP 하나 제거     +0.0016
TP=0 클래스의 FP 하나 제거     +0.000069      ← 196배 차이
TP 하나 잘못 지움              -0.0048
FP 삭제 손익분기 정밀도         0.833 (test) / 0.802 (val)
```
음수 MCC 클래스(6개)가 전체를 깎는 양은 **−0.0026 뿐**이다. FP 제거 축은 실질적으로 무가치.

## 28. 과적합 검사 도입 — 채택 기준을 세 겹으로
"test·val 동시 양수"만으로는 부족하다는 것이 실증됐다. 케이스 단위 부트스트랩 1000회 추가:
```
                바뀐케이스  ΔMCC52   95% CI              Δ>0     판정
TOPK_FRAC(d2007)     8    +0.0000  [+0.0000,+0.0000]   0.0%   구조적 0
접합부 jbp12 test    1    +0.0057  [+0.0000,+0.0092]  42.5%   아티팩트
접합부 jbp12 val     1    +0.0002  [+0.0000,+0.0009]  39.9%   아티팩트
COLD 헤지 test      19    +0.0182  [-0.0020,+0.0306]  87.0%   실재
COLD 헤지 val       11    +0.0244  [-0.0021,+0.0368]  87.7%   실재
```
`jbp12` 는 test·val 둘 다 양수라 기존 규칙은 통과하지만 **각각 케이스 1건**이 만든 숫자다.
부트스트랩이 없었으면 +0.0065 를 성과로 올렸을 것이다.
**신규 채택 기준: ① 두 집합 양수 ② 바뀐 케이스 수 충분 ③ 부트스트랩 Δ>0 ≥ 50%**

## 29. COLD 헤지 — 효과는 실재, 배포 불가로 종결
"제출물 전체에서 미예측인 클래스에 2·3등 후보를 붙인다". 두 split 87% 재현.
그러나 컨테이너는 **케이스 단위 호출**이다(`pipeline_case.py --image <1개>`,
README_BUNDLE "1케이스", GC 케이스당 7분). 제출물 스코프를 볼 수 없어 배포 불가.
→ 메커니즘("TP=0 클래스에 배출하면 MCC 상승")은 검증됐다. 남은 일은 **케이스 단위로
배포 가능한 클래스 선정 규칙**을 찾는 것. 진행 중: `rare`(학습표본 게이팅),
`pair`(train292 혼동쌍 표 게이팅, 적중 9~60%).

## 30. 재학습 없는 대안 — 시도와 결과
```
후처리 가지치기 되돌리기   ✗ 가공 전후 소분지 존재 수가 완전 동일 (min_cc_vox 는 무관)
분기점 추출 완화          ✗ spur 2.0→0.8 · junction_r 2.0→3.0 해도 앵커율 +0.0~4.8%
Pcom+AChA 축 병합         ↻ AChA 가 test 81/83 케이스에 그려짐(GT 60.7%) = 정보량 0
소분지 확률 문턱          보류 (37클래스 × 전볼륨 = 케이스당 5.8GB)
좌우 대칭 앵커 보간        미시도
```
**앵커 부족은 실재한다**: 큰 혈관 98.8% vs 소분지 57.8~62.7%. 원인이 곁가지 가지치기가
아니라는 것만 밝혀졌고, 연결성인지는 `anchordiag` 진행 중.

## 31. arc 접힘 버그 — 수정했으나 실익 없음
`cand.sort(); d1,d2=cand[0],cand[1]` 로 **t ≤ 0.5 로 접혀** 있었다(실측 max 정확히 0.5000).
방향 부호를 넣어 [0,0.9716] 로 폈으나 미도달이 8→122 로 악화. 그리고 FP 담당이 확인한 대로
**같은 정보(d_term)가 이미 `--use-pos` 에 있다** — 3.1↔3.7 AUC 1.000 vs arc_t 0.683.
"최근접 분기점 2개"가 병변을 사이에 두는 비율이 24% 뿐이라 부호만으로는 못 고친다.

## 32. 배출의 부호는 적중률이 아니라 **표적 클래스의 생사**가 결정한다
같은 "2등 배출" 메커니즘인데 표적에 따라 부호가 뒤집힌다:
```
죽은 클래스(TP=0)에 배출   오답 1건 -0.000069   COLD 헤지: MCC +0.018 · 두 split 87% 재현
산 클래스에 배출          오답 1건 -0.0016     혼동쌍:   MCC -0.030
```
혼동쌍(train292 에서 P(GT=B|1등=A) 가 9~60% 인 쌍)을 배출한 결과:
```
배출량   ΔMCC52(test)   Δ6지표52   ΔMCCcg    Δ6지표cg
 32건     -0.0303       -0.0325    -0.0438   -0.0423
 14건     -0.0112       -0.0147    -0.0161   -0.0165
  5건     -0.0068       -0.0064    -0.0098   -0.0092
val 32건  -0.0159       -0.0184    -0.0251   -0.0239
```

**손해가 배출 건수에 정비례** → 최적 배출량 0. 단가표(오답 -0.0016)와 수치가 맞는다.
그리고 train292 쌍 확률 9~60% 가 test 에서 **적중률 3.1%** 로 무너졌다(32배출 1적중).
게이트 탐색 때와 같은 비전이다.

## 33. Pcom+AChA 병합 — 기각
```

val   -0.0239 (6지표)
```
"AChA 채널은 어디나 켜져 있어 정보량 0" 이라는 진단이 **틀렸다**. 병합하면 TP 2개를 잃는다.
어디나 그려져 있어도 거리값의 미세한 차이가 실제로 쓰이고 있었다.

## 34. 앵커 부족의 진짜 원인 — 부모 혈관과 **끊어져 있다**
`c4_branchpoint_graph.py` 의 노드는 "서로 다른 혈관 라벨이 만나는 지점"(n_transition_vox)이다.
접촉이 없으면 노드가 생기지 않는다. val 42케이스 × 좌우 실측:
```
          앵커없음   그 중 ICA 비접촉      앵커없는 성분 크기 중앙
AChA        30         27 (90%)              31 복셀
OA          24         22 (92%)             478 복셀
Pcom        16         12 (75%)               7 복셀
```
그래서 `SPUR_MM 2.0→0.8`·`junction_r 2.0→3.0` 을 해도 앵커율이 +0.0~4.8% 밖에 안 올랐다
(곁가지 길이 문제가 아니었다). `close_mm` 도 답이 아니다 — `close_class` 는 **클래스별**로
작동해 AChA-ICA 같은 이종 클래스는 절대 연결하지 않는다.

**해법**: 끊어져 있어도 기시부는 정의할 수 있다. 소분지에서 부모 혈관에 가장 가까운 점이
해부학적 기시부다. 그 지점을 pseudo 노드로 넣으면 연결 여부와 무관하게 앵커가 생긴다.
`pseudo_anchor.py` (bp json 후처리, maxgap 8mm). 재학습 아님. 진행 중.

## 35. 계산만으로 닫은 가설 (실험 슬롯 미사용)
```
중복 클래스 재배정   한 케이스 같은 클래스 중복 = test 1건 · val 2건 → 상한이 아티팩트 구간
빈 예측 케이스 구제   GT 있는 빈 예측 = test 3건 · val 3건 → 상한 6건, 게다가 위치를 찍어야 함
후처리 가지치기      가공 전후 소분지 존재 수 완전 동일
```

## 36. 배출 계열 종결 — 세 방식의 대비가 원인을 특정한다
```
표적 선정 방식                새 TP   새 FP   ΔMCC52(test)   배포
COLD (제출물에서 미예측 클래스)   +2     +19     +0.0182       ✗ 케이스단위 불가
혼동쌍 (train292 쌍 확률 9~60%)  +1     +31     -0.0303       ✓
희귀 ≤5 (학습표본 고정목록)      +2     +37     -0.0123       ✓
희귀 ≤10                       +2     +55     -0.0331       ✓
```
**셋 다 새 TP 를 만든다. 메커니즘은 작동한다.** 부호를 가르는 건 오답의 가격이고,
그건 표적 클래스가 죽었는지(TP=0) 살았는지가 정한다 — 죽은 클래스면 -0.000069, 산 클래스면 -0.0016.

"희귀하다"(학습표본이 적다)나 "혼동된다"(train 쌍 확률이 높다)로는 **"죽었다"를 근사할 수 없다.**
희귀 범위를 ≤5 → ≤10 으로 넓혀도 새 TP 는 2개 그대로이고 FP 만 37→55 로 는다.
죽은 클래스는 그 제출물에서 실제로 아무도 예측하지 않은 클래스이고, 그건 전체를 봐야 안다.
`pipeline_case.py --image <1개>` · README "1케이스" · GC 케이스당 7분 → **원리적으로 불가능**.

## 37. 부트스트랩이 판정을 네 유형으로 가른다
```
구조적 0     TOPK_FRAC          CI [+0.0000,+0.0000]   Δ>0   0.0%
확실히 나쁨   pr09 / pr17 / pr29 CI 전구간 음수          Δ>0   0.0~1.6%
아티팩트     jbp12 test/val     CI 하한 0.0000          Δ>0  42.5% / 39.9%
실재하는 이득 min_vox · COLD     CI 하한 0.0000          Δ>0  85.0~87.7%
```
`jbp12` 와 `min_vox` 는 CI 모양이 비슷한데 Δ>0 비율로 갈린다(42.5% vs 85.0%).
바뀐 케이스가 1건이냐 3건이냐의 차이다. **CI 만 보면 안 되고 Δ>0 비율을 같이 봐야 한다.**

## 38. pseudo 앵커 — 앵커율은 올렸다
```
test        현행 → pseudo         val         현행 → pseudo
R-OA      62.7% → 95.2% (+32.5)   R-OA      71.4% → 90.5% (+19.0)
L-OA      71.1% → 94.0% (+22.9)   L-OA      71.4% → 92.9% (+21.4)
R-AChA    57.8% → 90.4% (+32.5)   R-AChA    64.3% → 85.7% (+21.4)
L-AChA    57.8% → 90.4% (+32.5)   L-AChA    52.4% → 90.5% (+38.1)
R-Pcom    60.2% → 73.5% (+13.3)   R-Pcom    57.1% → 66.7% ( +9.5)
L-Pcom    63.9% → 75.9% (+12.0)   L-Pcom    54.8% → 69.0% (+14.3)
```
Pcom 만 덜 오른 이유: 앵커 없는 Pcom 성분 크기 중앙이 **7복셀**이고 Pcom 라벨 자체가
없는 케이스가 21건이다. 없는 것은 만들 수 없다.
학습 bp(417 참조)도 같이 보강해 train/eval 을 맞춘 뒤 피처 재생성 → e2e 진행 중.
